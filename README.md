# Sandlot Parkour App

Sandlot Parkour App is a web application built for providing statistics for Minecraft players and parkour courses. ParkourStats is currently exclusively compatible with PostgreSQL databases generated by the [Parkour](https://github.com/A5H73Y/Parkour) plugin created by [A5H73Y](https://github.com/A5H73Y).

This app has been developed using an [Express](https://expressjs.com), [PostgreSQL](https://www.postgresql.org), and [TypeScript](https://www.typescriptlang.org) backend leveraging the use of [Prisma ORM](https://www.prisma.io), and a [React](https://react.dev), [TailwindCSS](https://tailwindcss.com), and [TypeScript](https://www.typescriptlang.org) frontend.

## Setup

**Prerequisites for local setup:** Git, Node.JS

Run the following commands to create a local instance of ParkourStats:
```
git clone https://github.com/Firepyth/SandlotParkourApp.git

cd SandlotParkourApp
```
Next you will have to create a .env file at the project root and add the following line to it:
```
DATABASE_URL=<postgresql_connection_string>
```
*replace <postgresql_connection_string> with your PostgreSQL server's connecction string. For help regarding PostgreSQL connection strings, see [this](https://www.geeksforgeeks.org/postgresql/postgresql-connection-string/) site.*

Once all of the previous steps have been completed, run the following two commands:
```
npm i

npx prisma generate

cd client

npm i

cd ..

npm run dev
```
Alternatively, run the following oneliner command and add in your PostgreSQL connection string to automate the entire setup process:
```
git clone https://github.com/Firepyth/SandlotParkourApp.git;cd SandlotParkourApp;echo 'DATABASE_URL=<postgresql_connection_string>' > .env;npm i;npx prisma generate;cd client;npm i;cd ..;npm run dev
```

## File Structure

| Path | Purpose |
|------|---------|
|/|Root directory for the Express API.|
|/src|Directory containing all source code for the Express API.|
|/client|Root directory for the client application.|
|/client/src|Directory containing all source code for the client application.|

## API Endpoints

| Endpoint path | Description   |
|---------------|---------------|
|GET /api/courses|Responds with stats on all parkour courses. Supports ?direction=, ?sort=, and ?search= for filtering and ?page= for paging.|
|GET /api/courses/{course_id}|Responds with stats for one parkour course. Includes record progression for the specified course.|
|GET /api/courses/completions/{course_id}|Responds with all leaderboard times for one parkour course (ignores repeat times from players). Supports ?direction=, ?sort=, and ?search= for filtering and ?page= for paging.|
|GET /api/players|Responds with stats on all players. Supports ?direction=, ?sort=, and ?search= for filtering and ?page= for paging.|
|GET /api/players/{player_id}|Responds with stats for one player.|
|GET /api/players/completions/all/{player_id}|Responds with all parkour courses for one player. Supports ?direction=, ?sort=, and ?search= for filtering and ?page= for paging.|
|GET /api/players/completions/finished/{player_id}|Responds with all finished parkour courses for one player. Supports ?direction=, ?sort=, and ?search= for filtering and ?page= for paging.|
|GET /api/players/completions/unfinished/{player_id}|Responds with all unfinished parkour courses for one player. Supports ?direction=, ?sort=, and ?search= for filtering and ?page= for paging.|
|GET /api/playercourse/{player_id}/{course_id}|Responds with stats for one player on one parkour course. Includes personal best progression.|
|GET /api/playercourse/completions/{player_id}/{course_id}|Responds with all parkour course completions for one player on one course. Supports ?direction= and ?sort= for filtering and ?page= for paging.|
|GET /api/playercourse/search|Responds with the top three course and player matches based on ?search= query.|
|GET /api/playercourse/recent|Responds with the five most recent courses and players.|
